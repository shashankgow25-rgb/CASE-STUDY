Executive Summary & Objectives

This web application serves as Case Study 1 for the Web Programming Lab, authored by Shashank Gowda (USN: 24BTRSN038). The project demonstrates the full implementation lifecycle of an event-driven client-side game application built with pure web technologies and deployed on GitHub Pages cloud hosting.

Core Lab Scope

Develop an interactive front-end application demonstrating DOM manipulation, state management, and responsive CSS grid design.

Audio Engine

Zero-dependency sound synthesis using HTML5 Web Audio API oscillators for win/loss audio feedback.

Deployment

Version controlled via GitHub repository and delivered publicly using GitHub Pages CD pipeline.

Problem Statement & Requirements

Conventional command-line implementations of decision games lack visual engagement, round telemetry, and modern user experience standards. The key requirement of this lab assignment is to engineer a complete GUI application fulfilling the following criteria:

  • Metadata Transparency: Top-bar academic card displaying student credentials (Shashank Gowda, 24BTRSN038).
  • Rule Precision: Unbiased computer selection using pseudo-random number generation combined with lookup matrices.
  • Match Mechanics: Configurable rules support (Endless, Best of 3, Best of 5) with automated victor detection.
  • Session History: Real-time table tracking every user gesture, opponent gesture, result, and timestamp.

Data Lifecycle Pipeline

1. Event Listener Trigger: Click event fires playRound('rock'|'paper'|'scissors').

2. Computer Generation: Math.floor(Math.random() * 3) selects opponent gesture.

3. Matrix Evaluation: Cyclic rules dictionary resolves WIN, LOSS, or DRAW.

4. State Mutation: Scores incremented, Web Audio frequency plays, and history log table updates.

JavaScript Logic & Algorithmic Explanation

Game rule evaluations avoid redundant nested conditional statements by utilizing a key-value mapping structure:

// Deterministic Win Dictionary
const rules = {
rock: 'scissors', // Rock beats Scissors
paper: 'rock', // Paper beats Rock
scissors: 'paper' // Scissors beats Paper
};
if (userChoice === cpuChoice) {
return 'DRAW';
} else if (rules[userChoice] === cpuChoice) {
return 'USER_WIN';
} else {
return 'CPU_WIN';
}

GitHub & GitHub Pages Step-by-Step Hosting Guide

Follow these Terminal commands and GitHub settings to host this application on GitHub Pages:

Step 1: Initialize Git Repository locally
git init
git add index.html
git commit -m "Initial commit - Case Study 1 RPS Application"
Step 2: Link to GitHub Remote Repository
git branch -M main
git remote add origin https://github.com/shashankgowda/rps-web-lab.git
git push -u origin main
Step 3: Enable GitHub Pages Cloud Deployment
  1. Navigate to repository on GitHub: github.com/shashankgowda/rps-web-lab
  2. Click on Settings $\rightarrow$ Pages (under Code and automation).
  3. Under Build and deployment, set Source to Deploy from a branch.
  4. Select main branch and folder / (root), then click Save.
